# Bảo V1 — verified-local-WAV amplitude puppet preview

Scope: Studio LAB PR #8 only. This is **NOT genuine audio/video lip sync** and not a realistic male or Owner likeness. It moves a small visual mouth bar on the existing *conceptual silhouette*, proportional to acoustic energy in a local verified WAV, not based on phonemes, speech recognition, text forced alignment, facial animation, rendered video, or any commercial presenter. It cannot establish spoken correctness in VI/KO, or high-quality performance.

Integration: the existing `BaoAudioTiming.verify()` already requires WAV byte SHA256 to match a strict 3-cue, exact-language/product manual manifest and validates PCM16 WAV. Only **after** the existing verifier PASS does app.js send a local in-document `honey:verified-local-wav` event containing the ephemeral ArrayBuffer, while every reset/product/language/new import/error sends `honey:local-wav-cleared`. The new `BaoMouthEnergy.envelope()` independently parses bounded RIFF PCM16 mono/stereo WAV data, rejects invalid rate and duration, aggregates absolute PCM energy into 20ms windows (bounded at 6000 bins), and maps RMS to a clamped `0..1` openness. `mouth_preview.js` displays an *audio-reactive bar* only for a verified sample, reads audio.currentTime on pause/seek/timeupdate/animation frames while playing, and fails closed/reset on errors. All text explicitly labels this **NOT LIP-SYNC**. No new decoder, file loader, media exporter, server, AI inference, mic, identity cloning or network path.

Narrow QA: pure Node unit tests for silence/tone, 16-bit WAV bounds, channels and malformed chunks. Real Windows Chrome end-to-end integrates with existing WAV manual timing, generates a one-second PCM fixture of silence for the first 500ms and synthetic tone for the second half, checks closed/open mouth at 450ms/810ms, and checks a deliberately wrong WAV SHA removes the player and visual cue. Existing 4-language storyboard, local SRT/VTT, desktop/mobile and no outbound network remain in the Chrome regression suite.

**Limitations:** amplitude animation can move during non-speech noise/music and has no phonetic alignment, mouth shape diversity, latency certification, 3D facial visemes, face tracking or live streaming. A future real-viseme engine should use authorized voice/media and independent AV QA and must not reinterpret this as a commercial/premium lip-sync PASS. Current model OpenRAIL-M legal preflight and real native VI/KO listening remain NOT_PROVEN. No paid API, no Production, no merge or customer outreach.
