## Why this host

GitHub Codespaces (personal-account included compute/storage quota, subject to actual account balance and billing controls) can preserve a private workspace across stop/restart. **Do not create a Codespace if it would exceed the free quota or incur unapproved charges.** The repo is public, but the Codespace owner account and its quotas are not inspected. Render Free is explicitly excluded because its local filesystem is ephemeral on restart and it does not support free persistent disks. Public hosted GitHub Actions runners are also excluded for Nous OAuth persistence because they are ephemeral.

## Setup with the minimum Owner identity action

1. In GitHub, use the **existing Draft PR #4 branch** `hermes-lab/actions-publisher-20261029-01` to open a Codespace. The branch's `.devcontainer/devcontainer.json` runs `codespaces_prepare.sh` only. This creates an unprivileged `honey-hermes-test` UNIX user and a private (0700) storage tree at `/workspaces/.honey-hermes-test`, **outside the repository**. It does NOT run a model, start Hermes, contact Nous, authenticate or export anything.
2. Once the TEST Codespace is ready, use one terminal command: `bash hermes_lab_local/codespaces_auth_bootstrap.sh`. The script verifies the pinned Hermes v0.22.5 Git SHA, installs the officially pinned dependencies as the unprivileged user and starts official `hermes auth add nous --type oauth` and `hermes setup --portal`. The **Owner completes the device-code/browser OAuth on the official provider page**. Never paste passwords, verification codes, refresh tokens, auth.json, GITHUB_TOKEN or gh credentials into ChatGPT, the repo, issues, PR logs or email. Only afterward `hermes portal info` can report a configured provider. This is necessary but not itself an E2E PASS.
3. Run `bash hermes_lab_local/codespaces_smoke.sh` once, in the same TEST Codespace. Under the isolated user (with a sanitized environment and no GitHub credentials), it asks Hermes for ONE tiny normalization function, with a 90-second outer wall time and max one agent turn. It retains all raw events and error details privately, rejects tool invocations, parses the official stream-json terminal envelope, independently validates the exact 1-function AST, and checks original **unchanged UTF-8 bytes** and SHA-256. Any failure stops, with no retry or GitHub write.
4. Only when that produces `HERMES_ORIGINAL_BYTES_PRIVATE_QA_PASS_NO_GITHUB_WRITE`, a **separate GitHub-authenticated Codespace operator**, *not the Hermes user*, can run `python3 -m hermes_lab_local.codespaces_broker` from the repo root. The broker independently re-reads the fixed private file, verifies exact original byte SHA/size/source pin + AST, requires an exact repo, exact existing branch and clean Git tree, checks remote HEAD=local HEAD, writes precisely `hermes_lab_local/generated/normalize_label.py` and `provenance.json`, then performs a **single non-force push** to the same existing LAB branch. No new PR/branch, no merge and no production write. Failed publication has an EFFECT_UNKNOWN marker and must be reconciled before any retry.
5. GitHub's independent, read-only scoped CI accepts only the verified generated file/receipt. **No self-declared model pass** counts as independent human/provider identity attestation.

**Credentials boundary:** owner OAuth is stored under the unprivileged test user's private Hermes HOME outside Git; `postCreate` must refuse if that user can read the default operator's GitHub CLI auth file. Hermes has no workspace write privilege to the repo and its command environment is reset. The publisher may use Codespaces' owner-scoped existing Git authentication only from the distinct operator process. The broker never sends any OAuth data, environment secret or raw diagnostic text to GitHub. The trusted Codespace administrator still controls the whole container; this is least privilege inside one owner-operated environment, **not hardware isolation**.
